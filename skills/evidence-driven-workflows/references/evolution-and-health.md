# 评价一次改动，并观察多轮效果

## 四种东西要能分开换版本

一次评估至少能定位输入与独立预期、被评产物、评价器、执行环境。输入清单包括开发样本、已知回归和保留样本；说明书、提示词或 judge 规则也是可版本化产物。修订哪个，就写清其他三个怎样固定。撤销改动时保留失败样本、旧规则和诊断，方便下一版执行者在同一位置重跑。

| 问题 | 如何做对照 | 能作出的决定 |
|---|---|---|
| 这次交付修好了吗？ | 同一冻结输入、同一评价器，比较旧/新版产物。错误样本应按预期失败，修正后该项及既有回归通过。 | 本候选的具体断言已修复。 |
| 检查器真的能抓到这种错吗？ | 对同一候选和同一组正确/故意错误样本，同时运行旧/新评价器。记录错例触发的具体分支；导入失败或超时单独记未决。 | 该评价器在这些样本上的检出能力。 |
| 改进能迁移吗？ | 在另一版本、另一来源家族或另一使用场景重放同一规则。新输入需触发目标机制。冻结独立预期和核心检查 ID，另记新加与删除的检查及分母。 | 可推广到已验证范围，或保持候选等待新区分性试验。 |
| 文案或提示词更可靠吗？ | 固定读者问题及来源，匿名提供旧/新稿，要求独立 agent 作答并引用依据。换问题或来源复核；若结论依赖排列顺序再换序。 | 明确哪些误解减少、哪些仍需真实读者或专家确认。 |

调参前登记什么结果支持采用，什么结果要求回退。保留样本按生成机制划分，如同一文献的不同 OCR、同一日志的近似拷贝不能当作两个独立输入。保留例一旦用于选规则，就转入回归集，并为下一次推广另找输入。遇到评审分歧时保存各自引用和反例，用能区分两种解释的材料裁决；证据不足可明确弃判。

工作流有两处反馈入口。其一是交付中的异常，例如读者问题暴露了缺少的适用条件。把它定位到原始断言、来源、实现或解释的具体环节。其二是工具本身，例如任务接管丢失断点、评价器没发现新增依赖。记录任务版本、复现命令、预期、实得、对谁造成返工；仅影响本项的故障局部处理。协调者在阶段交接时查重，创建或关联一个有负责人和成功条件的维护任务。隔离试验后，在原任务或阶段记录中回填修订、结果和恢复版本。

## 全局观察如何作出可行动的判断

接手长程目标、阶段收口或既有复盘周期到来时，从权威队列的一致读快照和固定产物取样。记录时间、队列历史上界与身份（如事件序号和前缀摘要）、各仓提交、评审包/轮次 ID。下一次与同一历史的前次快照比较。队列恢复了旧备份、统计口径变更或材料缺失时说明差异，不能计算的分母记未知。

| 观察维度 | 至少看什么 | 可采取的动作 |
|---|---|---|
| 工作是否能流动？ | 各 goal/stage 的已交付数/计划数、两次均就绪的对象、等待谁、持有人、共有资源和事件增量。 | 对照真实优先级。下游等待同一缺口时把该缺口拆成能提前交的最小对象；无需求的旧任务按项目规则延期并留原因。 |
| 结果到达了使用者吗？ | 有消费证据的断言数/本阶段需要消费的断言数；独立作答并复审的项/应审项。抽一个 ID 从读者答案回到原文和行为。 | 正文误读修说明；接口不足退回实现；模型范围由来源复核。保持各类验收的状态。 |
| 修复还会再犯吗？ | 在相同失效机制上计算受影响的**不同候选**。同时列本候选恢复数、在其他候选同一规则下验证过的恢复数/可比较的恢复数。 | 查两份原始诊断排除同名异因。若同类失效重现，为预防方案设一个有区分度的下一轮试验。 |
| 观察口径还可靠吗？ | 错例检出、检查覆盖变化、环境失败、丢失包、未知项、题集泄漏。范围不匹配的多候选比较保留原始包。 | 检查器退化则复用旧版交叉验证；历史告警保留版本，用当前候选的原始证据判断现状。 |

每次观察至少交代当前证据支持哪个判断、受影响的对象、上次预测的结果，以及尚有意义的下一动作。用一条最有依据的改进任务闭合即可。没有新增材料时记录“本窗口无新证据”。阈值由项目的风险、样本量和等待成本决定；吞吐量、总分或连续全绿单独不足以证明工作方法改善。

**采用、保留候选、回退。** 目标失效被检出、有效输入未受损、既有回归保持、独立样本支持推广时，固定采用范围与版本。只修复原场景、只有合成样本或未覆盖真正触发条件时，注明“保留候选”，写明待验证的预测和触发时机。出现误拒、漏检、不可接受的成本或覆盖退化时，恢复已知可工作的默认版本，保留此次反例。交付物、评价器、文档可以作出不同决定。
