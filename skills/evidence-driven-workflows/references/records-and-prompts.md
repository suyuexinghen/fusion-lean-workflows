# 记录和提示词

以下为可裁剪字段。已有 Git、issue、CI 或数据目录能提供的内容直接引用。使用项目已有格式即可，不必另造一套表。

## 断言与验收卡

```text
稳定 ID / 读者要据此作出的判断 / 谁消费它
原始来源及定位 / 版本或哈希 / 适用域、约定与例外
公开入口 / 被承诺的行为或结论 / 明确未覆盖的范围
独立预期及确定时间 / 一个正确例 / 一个定点错例及它应触发的错误
固定产物和依赖 / 复跑命令 / 预期、实得和退出状态
机器结果 / 逐条 agent 裁决和理由 / 真实使用或领域签审（如适用）
```

## 任务、接手与恢复

```text
任务 ID / 目标与阶段 / 上游 ID / 下游接收方 / 独立性约束
最小可检验产物 / 唯一负责人或 session / 共写资源 / 当前修订号
交付或移交版本 / 已通过的最后一步 / 首个阻塞点 / 接手动作及成功条件
```

遇到读者或评审异议，把问题句、候选、反例和预期结果挂回原 ID，使用单独修订任务；待修订提交后，从新版本重新核对受影响的项。临时换人时交接所有权，控制过期写入。重复导入同一批任务或重试交付时保持原有事件可查。

## 评估包与改进决定

```text
问题与根因假设 / 在哪些不同候选复发 / 首条原始诊断
冻结输入及来源家族 / 独立预期 / 环境与候选版本
旧规则、候选规则或提示词版本 / 同输入前后对照 / 命中的错例
区别于开发样本的另一输入 / 保留例结果 / 覆盖变化、代价和未知
决定（采用、保留候选、回退）及适用范围 / 恢复版本
下一阶段预测、触发条件和观察者 / 回填的原任务或读者断言 ID
```

## 长程任务的启动词

将尖括号处替换成真实目标与入口。Codex 可用 `$evidence-driven-workflows`，Claude Code 可用 `/evidence-driven-workflows`。使用宿主支持的目标和任务机制。

```text
在 <项目> 的既有仓库与任务系统持续推进到 <具体验收终点>。输入优先取自 <本地原始资料/规格/反馈>。先读取当前版本、在途任务和最近的验收包，从 <一个读者或使用者问题> 固定独立预期与辨错输入。在 <真实消费入口> 验证并把结果绑定固定版本；独立审读 <必须判断的解释或边界>。每次交付后领取下一项，阻塞时记录恢复条件并推进独立分支。阶段收口比较上次全局快照。对复现的流程问题提出一个可回滚改动，在同一输入和独立输入上复验后给出采用、保留待验或回退的依据。按 <授权范围、资源限额、外部签审和结束条件> 收口。
```

## 给独立 judge 的任务

```text
你收到的材料是固定版本的 <原始定位>、<读者问题> 和 <评价维度>。先独立作答并保存答案及引用。再打开 <匿名候选>，逐项记录断言 ID、支持/冲突/无法判定、理由、可推翻它的输入、物理或业务前提。标明是文字、实现、来源还是评价方式的缺口。提交原始记录和所审版本。作者交回新版本后，复核异议是否消失及相邻断言是否受影响。
```

## 给阶段协调者的复盘任务

```text
在 <固定时间/事件序号> 冻结全体目标及三类产物的版本，与 <前次观察> 比较。查两次都就绪的项、依赖最集中的地方、收到独立复验和实际消费的产物。对上轮 <改进预测> 找不同候选的同类触发场景，列分母、同版评价器结果、缺失证据与复发差异。若值得调整，引用已有任务或建立一项有负责人和验收条件的新试验。保留历史告警，并注明当前版本是否仍受影响。
```
