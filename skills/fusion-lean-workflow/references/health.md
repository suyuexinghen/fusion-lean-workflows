# 读阶段健康报告

`fusion-task health` 读取 SQLite 当前状态与事件、配置根下的 Git HEAD 与固定版本中的轮次记录。已有报告可用 `health --previous <报告.json>` 比较。观察时保存输出、仓库版本、事件上界与所用规则。需要四仓的目录结构见[四仓交接](compute-workflow.md)，历史三仓场景可省略计算仓。

| 观察 | 回到哪里核对 |
|---|---|
| 等待、停滞和换人 | 对比上次观察的可领任务和事件，定位前置、资源与当前负责人。 |
| 岗位交付与实际消费 | 区分计划边、下游完成和固定证据中的实际使用。给比例注明分子、分母和缺件样本。 |
| 独立审读 | 查看声明过的独立性边和实际会话；正式裁决应绑定终稿和 review 文件。独立性缺失时保留诊断。 |
| 同一候选恢复 | 把修前、修后和带错对照放在同一候选、评价器和输入范围比较。 |
| 另一候选防复发 | 要求另一固定版本、独立输入或相应新样本，同一组检查和带错对照能辨别旧缺陷。 |

在运行历史中同时保存重复失败和后续修复。评价器更换后的试验另记录候选、判据、覆盖诊断和负控。无后续样本就保留待观察，分母为零就报告证据缺口。报告中的提示指向原始文件和任务，协调者据此安排下一项。[通用的对照与采纳规则](../../evidence-driven-workflows/references/evolution-and-health.md)
