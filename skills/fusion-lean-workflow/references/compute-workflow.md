# Fusion Lean 的四仓交接

| 仓库名 | 交付物 | 下游如何核对 |
|---|---|---|
| `fusion-lean` | 定义、公开定理、前提明确的陈述与消费例 | 固定 Git 版本，从项目公开入口编译，比较量词和前提。 |
| `fusion-compute` | 调用入口、数值算例、固定输入及 `runs/<ID>/run.json` | 同一版本复跑正常例、边界例和带错对照。 |
| `fusion-lean-wiki` | 读者题、适用域解释、引用、独立答案与审读记录 | 将主张和对应的来源、运行证据与稿件版本逐项对应。 |
| `fusion-lean-skills` | 任务图、角色、固定用例、评价器与改进决定 | 对照旧规则与新规则，在独立候选上复验。 |

C 与 B 可并行准备独立预期及接口。需要传播给读者时，由 editor 收证据撰文，judge 先按来源盲答，再对照固定稿。是否允许协调者并行调度，取决于实际依赖和会话可用性。

数值记录注明软件版本、实际执行入口、命令及退出码，给出输入摘要、单位、约定、误差阈值与来源、实测结果及覆盖域。数值误差与适用域随输入给下游。对于同一软件的第二份输出，要核实它是否共享了被检验的转换逻辑。Lean 一般声明、有限精度算例与实验观测各自使用相应证据。

检查独立预期提交顺序时，从 Git 找预期文件第一次出现的提交，以及任何实现路径第一次出现的提交。实现路径清单包含计划和实际交付两边。核实预期提交严格早于实现且没有夹带实现文件。Git 证明版本顺序，预期内容由来源和独立复算确认。[通用记录模板](../../evidence-driven-workflows/references/records-and-prompts.md)
